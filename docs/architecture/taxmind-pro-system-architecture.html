TAXMIND PRO · SYSTEM ARCHITECTURE

税务知识图谱增强型智能咨询与风险审查平台

面向税务师事务所、代理记账公司与财税咨询机构。架构由“离线知识生产链”和“在线专业问答链”组成，以统一证据主键连接原文、条款、向量索引、图谱关系、风险规则与审核记录。

在线请求、检索与回答 离线数据加工与知识发布 审核、反馈与更新闭环

01 · 总体主架构

八段主链路 · 在线请求从应用入口回到检索路由 · 全链路证据可追溯

02 · 离线知识生产链

政策进入RAG与图谱链；官方问答和机构FAQ经审核后形成独立知识资产，并绑定正式条款

03 · 在线 GraphRAG 专业问答链

加入长短期记忆与FAQ加速层；任何FAQ命中仍须回查政策时效、地区、主体和正式条款

04 · 模块职责与串联说明

职责按业务边界拆分，避免把所有能力堆入一个“智能问答服务”

1. 数据采集

从税务总局、财政部、广东及深圳税务局等公开白名单来源获取政策、解读、指南与附件，保留来源和采集记录。

2. 数据处理

完成解析、OCR、清洗、去重、元数据标准化、时效识别及条款父子分块，为两条知识链提供一致输入。

3. 知识图谱

构建政策沿革、优惠条件、排除条件、涉税义务、风险规则和办税事项关系；重要关系必须回溯原始条款并审核。

4. 统一存储

MySQL作为结构化主库，MinIO保存原文，Milvus保存向量索引，Neo4j保存图谱关系，Redis保存短期会话状态；统一ID完成证据对齐。

5. 检索路由

识别七类业务任务，先校验主体、日期、地区和事实完整度，再决定精确、语义、图谱或规则检索组合。

6. 检索服务

并行执行关键词、向量、FAQ、图谱和规则检索，再进行重排、过滤、去重、父块回填和关系证据展开。

7. 生成与问答

确定性规则负责风险和条件判断，LLM负责问题理解与解释；生成后再次验证引用、时效、地域与责任措辞。

8. 应用接口

通过对话、事项、政策、FAQ、风险、办税、审核和知识后台承接专业用户工作，完成权限控制、日志记录和结果返回。

9. FAQ知识模块

管理官方热点问答和机构审核FAQ，保存标准问题、问题变体、标准答案、适用范围与政策依据；未审核对话不得进入FAQ库。

10. 会话与记忆管理

Redis维护当前会话工作记忆，MySQL保存事项长期记忆；只有审核通过的FAQ和机构案例才建立向量索引用于跨会话召回。

串联关系：官方资料经处理后进入RAG、图谱和FAQ构建链；专业用户从应用接口提交问题，Redis维护当前工作状态，MySQL提供已确认事项事实。检索路由组合关键词、向量、FAQ、图谱和规则检索形成证据集；确定性规则与大模型生成分析结果，经引用和安全校验后返回工作台。审核通过的FAQ或案例才能成为机构长期经验，审核反馈继续驱动知识修订与评测回归。

05 · 存储与记忆分配

原始文件、结构化主数据、派生索引、图关系和会话状态分别管理，避免职责混用

存储保存内容系统定位与管理规则
